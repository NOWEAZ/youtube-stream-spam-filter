# 댓글 방패 — 유튜브 스팸 댓글 차단 확장 프로그램

PC 크롬에서 유튜브 댓글을 읽을 때 **스팸 의심 댓글에 근거를 달고 접어 주는** 확장 프로그램입니다.
서버 없이 브라우저 안에서만 동작하고, 댓글을 삭제하거나 신고하지는 않습니다.

- **스팸 의심**: 점수가 기준을 넘은 댓글. 이유를 보여 주고 (설정에 따라) 접습니다.
- **검토 필요**: 근거가 일부 있는 댓글. 배지만 달고 접지 않습니다.
- 둘 다 아니면 아무것도 표시하지 않습니다. “근거 없음”은 안전하다는 뜻이 아닙니다.
- 어떤 판정에도 **‘정상입니다’**(또는 검토 필요에는 **‘스팸입니다’**) 버튼이 있고, 눌러 둔 문장과 비슷한 댓글은 다음부터 그대로 따릅니다.

## 설치 (5분)

1. 이 폴더를 내려받아 압축을 풉니다.
2. 크롬 주소창에 `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 프로젝트의 **`extension` 폴더** 선택
4. 유튜브 영상(`https://www.youtube.com/watch?v=…`)을 열고 댓글까지 스크롤합니다.
5. 툴바의 방패 아이콘을 누르면 분석 건수와 설정이 보입니다.

권한은 `storage`(설정·사용자가 표시한 기록 저장)와 유튜브 페이지 접근뿐입니다. AI 추가 검토를 켤 때만 Upstage 접속 권한을 따로 묻습니다.

| 한국어 키워드뿐이라 영어(UCI) 스팸을 못 잡음 | 한국어+영어 규칙. 자기 채널 홍보, 구독 요청, 도박·성인, 사칭·당첨, 연락처·수익 홍보 등을 **점수 합산**으로 판정 |
| 키워드 몇 개의 if문 | 신호별 가중치 + 조합 가산점 + 임계값 3단계(엄격/보통/느슨). 판정 이유를 화면에 그대로 표시 |
| 예측값이 LSH 참조에 쌓여 오판이 전파됨 | 참조에는 **독립 근거로 확정한 스팸**과 **사용자가 직접 확인한 라벨**만 넣고, 유사도만으로 스팸이 된 댓글은 참조에 넣지 않음. 평가 스크립트는 train의 정답 라벨로만 참조를 만듦 |
| 정상 반복 댓글(“1등”)과 복붙 스팸 구분 못 함 | 20자 이상 문장이 서로 다른 계정에서 3번째 반복되면 가산점, 같은 계정이 반복하면 더 큰 가산점. 짧은 반복은 제외 |
| 사용자 피드백이 영상 하나에만 적용 | ‘정상입니다/스팸입니다’를 `chrome.storage`에 저장해 이후 영상에도 적용 (최대 각 200개, 지우기 버튼 있음) |

| 결과 파일이 `.gitignore`로 커밋 불가 | `reports/`는 추적 대상 |

| 실제 크롬 검증 없음 | Chromium에 확장을 실제로 로드해 가짜 유튜브 DOM으로 검증하는 E2E 포함 (아래) |

## 동작 방식

```
댓글 감지 (MutationObserver)
  → 텍스트·링크 추출 → 유튜브 내부 링크 제외, redirect 해제
  → ① 악성 URL: Bloom Filter 양성일 때만 서비스 워커가 IndexedDB에서 정확 조회
  → ② 규칙 점수: 연락처·수익·행동유도·자기홍보·사칭·도박·링크·스타일 신호 합산
  → ③ MinHash+LSH: 확정 스팸과 유사 / 같은 영상 복붙 반복 / 사용자가 정상 표시한 문장과 유사
  → (선택) ④ ‘검토 필요’만 Upstage Solar 추가 검토
  → 표시(근거·접기·피드백) + 통계 갱신(DGIM, Flajolet-Martin)
```

| 알고리즘 | 쓰는 곳 | 세부 |
|---|---|---|
| Bloom Filter | 악성 URL 후보 선별 | 오탐률 1%, k=7 안팎. **미탐 없음**, 오탐은 정확 조회가 걸러냄 |
| Shingling + MinHash + LSH | 유사·반복 댓글 | 문자 3-shingle, 서명 64개 = 16밴드×4행, 후보는 Jaccard로 재확인. 후보 확률 `1-(1-s⁴)¹⁶` |
| DGIM | 최근 100개 중 스팸 의심 수 | 정확한 수와 함께 팝업에 표시 |
| Flajolet-Martin(PCSA) | 스팸 속 서로 다른 URL·계정 수 | 정확한 수와 함께 팝업에 표시 |

**링크 판정:** 링크는 여러 신호의 합으로 봅니다. 악성 URL 목록에 있으면 바로 스팸 의심이고, 목록이 비어 있어도 다음은 점수에 반영됩니다.
단축 URL·링크 모음(bit.ly, linktr.ee 등) +1.5, 의심스러운 주소(`.xyz`·`.top` 등 비정상 TLD, IP 주소, 퓨니코드, `user@` 형태) +1.5, 링크만 있고 설명이 거의 없는 댓글 +1.5, 서로 다른 사이트 링크가 여럿 +0.75, 메신저 초대 링크(t.me 등) +2, 외부 링크 포함 +0.5.
그래서 링크 하나만 있으면 ‘검토 필요’, 단축 URL이나 이상한 주소가 섞이면 ‘스팸 의심’이 됩니다. 설명이 충분한 글에 붙은 일반 링크와 위키백과·GitHub 등 신뢰 사이트 링크는 표시하지 않습니다.

판정 임계값: 보통 기준 **검토 필요 ≥ 1.5점, 스팸 의심 ≥ 3.0점**. 신호와 가중치는 `extension/core.js`의 `SIGNALS` 한 곳에 있습니다.

## 악성 URL 목록 넣기

기본 목록은 **비어 있습니다.** 가짜 위협 정보를 넣지 않았습니다. 실제 목록(URLhaus 등)은 이용 조건을 직접 확인한 뒤 내려받아 변환하세요. 도구는 아무것도 다운로드하지 않습니다.

```bash
node tools/build_blocklist.js --input urlhaus.csv            # 정확한 URL만
node tools/build_blocklist.js --input urlhaus.csv --hosts    # 호스트(domain:)도 추가 (정상 호스팅 도메인 오차단 주의)
node tools/build_blocklist.js --input my_list.txt            # 한 줄에 URL 또는 domain:example.test
```

`extension/data/blocklist.json`(정확 조회용)과 `blocklist.bloom.json`(Bloom Filter)이 만들어집니다. 확장 프로그램을 새로고침하면 새 목록을 IndexedDB로 가져옵니다.

## 선택 기능: AI 추가 검토 (Upstage Solar)

기본은 **꺼짐**입니다. 팝업에서 직접 키를 넣고 켜면 `검토 필요` 댓글만 한 건씩 보냅니다. 본문(최대 800자)·링크·규칙 근거가 전송되고 작성자 정보는 보내지 않습니다. 분당 6건·시간당 60건 상한, 8초 제한, 실패하면 규칙 판정을 그대로 씁니다. API 키는 이 브라우저의 `chrome.storage.local`에 평문으로 저장되므로 공용 PC에서는 쓰지 마세요.
모델명 `solar-pro4`와 채팅 API 형식은 Upstage 문서와 대조했지만, **실제 키로 호출해 본 검증은 하지 못했습니다.**

### 이번에 확인한 것 (2026-11-09)

- 단위 테스트 13개 통과 (Bloom 미탐 0과 오탐률, DGIM 오차 한계, FM 중복 불변, LSH 재확인·제거, URL 정규화, 규칙, 차단 목록 정확 조회, 오판 전파 방지, 사용자 피드백).
- E2E 통과: Chromium에 확장을 로드해 가짜 유튜브 DOM에서 정상·스팸·검토 판정, 같은 영상 타임스탬프 링크 무시, 차단 목록(Bloom → IndexedDB) 적중, 3,000자 URL이 있어도 대기열이 안 막힘, 접기·복원, ‘정상입니다’ 학습, 동적 댓글 추가, 오류 로그 0건.
- 추가 E2E 통과(13개 항목): 댓글 1,500개를 약 3초에 처리(가장 긴 화면 멈춤 60ms대), 빈 글·10만자·이모지 300개·제로폭/전각 문자 우회·주입 문장에서 오류 0건, 같은 노드의 본문이 바뀌는 경우(가상 스크롤) 재분석, 자동 접기·민감도·필터 끄기 설정 즉시 반영, ‘스팸입니다’ 학습이 새로고침 뒤에도 적용, 다크 모드, AI 검토 경로(가짜 Upstage 응답으로 검토 필요만 전송·작성자 정보 미전송·오류/비정상 응답 시 규칙 판정 유지·분당 6건 상한·끄면 미전송).
  - 이 테스트가 **실제 버그 하나를 잡았습니다**: 한 번에 500개 넘는 댓글이 대기열에 들어오면 넘친 댓글이 분석되지 않던 문제(수정 완료, 상한 300개 + 넘친 댓글 자동 재수집).
- 벤치마크(seed 42): Bloom 오탐 실측 1.0~1.1%(이론 1.0%), 미탐 0. LSH 후보 확률 실측이 이론 곡선과 4%p 이내로 일치. FM(PCSA, m=64) 평균 절대오차 약 6~10%(최대 tail 기준선 방식은 150~270% 과대추정). DGIM 최대 오차는 50% 이하.

### 아직 확인하지 못한 것 — 꼭 직접 확인하세요

- **실제 유튜브 페이지에서의 동작.** 이 환경에서는 유튜브에 접속하지 못해 `#comments ytd-comment-view-model`, `#content-text`, `#author-text`, `#published-time-text a` 구조를 가짜 DOM으로만 검증했습니다. 팀 데모의 VALIDATION.md는 이 선택자가 실제 페이지에서 맞았다고 기록했지만, 유튜브 화면이 바뀌면 `content.js`의 선택자를 고쳐야 합니다. 설치 후 실제 영상 몇 개에서 꼭 확인하세요.
- **UCI·한국어 실제 데이터 성능.** UCI를 내려받지 못해 실행하지 못했습니다. `data/sample_labeled.csv`(92건)는 제가 규칙을 만들면서 직접 쓴 스모크 테스트용이라 100%가 나와도 성능 근거가 아닙니다. 실제 데이터로 `evaluate.js`를 돌려 보고, 놓친 스팸·잘못 잡은 정상 예시(리포트에 출력)를 보며 `SIGNALS`를 조정하세요. 이때 test 결과를 보고 규칙을 고치면 test가 더는 독립이 아니니, 조정은 train 오류로만 하세요.
- 실제 Solar 호출, 실제 URLhaus 목록.
- 확장 프로그램 지연(p95)은 측정하지 않았습니다. Node에서 잰 엔진 처리 시간은 짧은 댓글 중앙값 약 0.1ms(p95 0.23ms), 1,500자 댓글 중앙값 약 0.4ms(p95 0.9ms)입니다. 브라우저 DOM 처리·화면 표시까지 포함한 지연은 아닙니다.

## 알려진 한계

- 이미지·동영상 속 글자, URL 단축 서비스의 최종 목적지, 동형 문자 우회, 새로운 스팸 문구는 잡지 못합니다. 규칙은 설명 가능하지만 일반화는 약합니다.
- 점수는 가중치를 손으로 정한 것이라 확률이 아닙니다. 민감도 3단계는 임계값만 바꿉니다.
- 라이브 채팅·Shorts·모바일은 지원하지 않습니다. 현재 DOM에 로드된 댓글과 답글만 봅니다.
- 같은 사람이 같은 문장을 정상적으로 두 번 쓰는 경우(같은 계정 반복)는 가산점을 받습니다.
- 차단 목록이 정확한 URL 일치라서, URLhaus 같은 깊은 경로 URL은 댓글에 올라온 링크와 일치할 확률이 낮습니다. `--hosts`를 쓸지 정하려면 적중률을 먼저 측정하세요.
